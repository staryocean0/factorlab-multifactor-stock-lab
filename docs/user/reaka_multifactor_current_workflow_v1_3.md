# REAKA 多因子选股当前工作流 V1.3

本私有仓库当前工作是**统一并验证文档、白皮书、代码、测试、工作流的正确口径，等待用户通知数据补齐**。本轮可以修复基础设施并运行合成测试，不运行策略训练、不选择 K、不运行账户、不代签金融回执，也不修改外部本地 FactorLab 的 current 指针。

唯一现行清单是 [current manifest@1.3](../ops/reaka_multifactor_current_manifest@1.3.json)，机器口径是 [foundation semantics@1.1](../ops/reaka_foundation_semantics@1.1.json)，完整解释见 [现行白皮书 V1.3](../ops/reaka_foundation_whitepaper_v1_3.md)。原 current@1.0、@1.1、@1.2 及其 source receipts 是冻结历史材料，旧文档中的“当前唯一动作”不再驱动本仓库。

## 读取与修改顺序

先阅读仓库 `AGENTS.md`、`README.md`、`docs/INDEX.md` 和 `NOTICE.md`，再读本工作流、现行清单、机器语义合同和现行白皮书。研究数据边界继续由 `docs/governance/data_usage_declaration.json` 约束。旧论文、旧工作流和历史审计用于理解来源及已知缺陷，不作为重新开放执行的入口。

需要改动数学或金融语义时，先在现行合同中明确对象、允许行为、证据来源和可反驳条件，再同步白皮书、代码、测试、工作流及新清单身份。只增补一份说明而保留相反的活动入口，不算五位一体完成。已封存历史摘要不可为通过新检查而重写；当前文件的合法升级通过新版本记录。

## 当前必须一致的口径

| 主题 | 正确口径 |
|---|---|
| 因子与论文 | 自研市场、大小盘、行业因子可作为输入；论文结果不能自动转移到本项目 |
| 条件与状态 | S_obs 是可观测上下文，不是 operator 标签或必然的市场真状态 |
| gate | `Z = Hy*G + Hx*(1-G)`；G 越大，收益编码占比越大 |
| K1、K2 | 矩阵下标与 N=1/2 容量实验分别表述；均不等于金融因子数或持股 TopK |
| 容量识别 | N_candidate 结果前冻结，模型不自动改变其矩阵数；N_used 是使用情况，N_selected 由后续研究选择；原始矩阵距离或潜能量差不能单独证明金融识别 |
| 三种残差 | 收益分解 epsilon_return、潜动力 residual_latent、账户 account_other 分开存储与解释 |
| 收益残差 | 使用此前冻结系数及相同截距约定，待真实收益成熟后才计算；不是已证明的个股 alpha |
| 残差预测 | 可以不启用，可以为零或无效；条件均值与条件分布分别验收，无必然正结果 |
| 正式预测证据 | 只用历史信息，hard selector；teacher-forced 去噪只作诊断；证书须与当前任务及支持绑定 |
| K 与残差次序 | 旧逐级 K 政策是可另行预注册的项目选择；不是论文定理，K2 失败不推出 K3 失败 |
| Stage4 | 旧持仓已实现贡献的条件关联，不是未来预测 IC；重复月份使旧证据无资格推进 |
| 数据与时钟 | 输入在决策时可见，标签已成熟，因子与收益同区间；补数据不重置已消费证据 |

现有 Stage4 的 2018-01、2021-01 在两个时钟分别重复，且组件覆盖不同。当前不是“只等用户金融签字”：必须先找回组件来源、验证覆盖和归因守恒，产生后继版本后才能重新提交金融判断。不得任意去重、复用旧通过字段或让用户替该缺陷签字。

## 本轮可执行验证

从仓库根目录运行以下两个独立步骤：

```bash
python scripts/validate_reaka_foundation.py
```

该命令只读检查现行基础设施，不要求市场数据补齐。严格模式的非零退出必须修复或明确报告，不能用 report-only 当作通过。它检查的是现行合同一致性和边界，不签署策略或历史证据通过。

```bash
pytest -q tests/unit
```

单元测试包括实际模型算式和合成反例，不构成模型训练或策略回测。纯 forward、合成面板构造和参考金融残差计算可以用于验证；实际拟合、研究执行及历史状态重写入口仍由现行边界阻断。测试应涵盖 gate 方向、矩阵查找与乘法方向、均值与分布对象区分、残差证书缺证及身份错配、重复月份拒绝和未开放动作阻断。环境缺少依赖或跳过相关测试时必须如实说明；不得把未执行的测试记为通过。

另可运行旧证据只读审计：

```bash
python scripts/audit_reaka_foundation.py
```

此命令专门保留 current@1.2 历史闭包检查，已知 Stage4 重复和来源缺口会报告失败或缺证。它不是现行基础设施入口，预期失败不应通过改写历史文件消除。工作流若为收集报告使用 `--report-only`，仅影响报告步骤退出码，报告中的错误、缺口和就绪状态必须原样保留。

用户正在单独上传 2023、2024 日线。保留包内全部数据及清单，不删减，不主动补造或下载 2026+ 数据。本轮不以市场数据完整性作为基础设施修复的前置条件，也不自行宣布上传完成。
