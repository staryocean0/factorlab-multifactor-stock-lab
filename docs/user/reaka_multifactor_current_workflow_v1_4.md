# 按任务和依赖开展研究：工作流 V1.4

当前版本由 [CURRENT.json](../../CURRENT.json) 指定，进度只读 [研究状态](../ops/research_state.json)，金融与数学解释只读 [白皮书](../ops/reaka_foundation_whitepaper_v1_4.md)。本工作流取代旧工作流中的临时全局关闭状态，不改写其历史记录。

## 1. 接手：先回答四个问题

确认实际分支与提交；用户现在要求回答什么金融或工程问题；哪些结论已有可追溯证据；本任务真正依赖哪些输入。main、PR 分支和用户本地 FactorLab 不必同步。未合并 PR 的改动不能说已经进入 main。

默认读 AGENTS、本工作流、状态文件即可。涉及方法时再读白皮书与对应实现/测试；涉及旧结果时沿该回执追来源。README、索引和云端说明只是导航，不是额外逐层审批或必读环路。

发现新的提交时，只比较与任务相关的变化。旧清单记载的“缺失”需要以实际树复核；文件已出现也不能自动变成已验收。不要因另一个 AI 口头说通过，就跳过必要的原回执核验。

## 2. 选择工作通道，不是从 R0 重做所有阶段

| 本次任务 | 可直接推进什么 | 什么时候才阻断 |
|---|---|---|
| 文档、索引、接口或基础设施维护 | 读取、修订、代码审查、现行检查、合成测试 | 改动触及未经理解的金融语义时先读对应定义；不等行情补齐 |
| 数学/方法预研究 | 推导、极端反例、可辨识性分析、比较候选、写隔离原型 | 不能拿合成结果证明真实市场盈利；不要求先找回所有旧产物 |
| 新的已授权经验研究 | 只核对该实验的输入、时钟、目标与预算，使用独立结果目录 | 其实际依赖缺失、存在泄漏或超出用户授权/资源边界；不是因为阶段编号较晚 |
| 原历史结果复现 | 绑定原身份、原字节及实际计算链 | 缺少影响该主张的来源时标记未复现；不可重盖旧章 |
| 正式评价或基线变更 | 使用与主张匹配的证据、同支持比较和明确身份 | 技术通过不能自动晋级；改变用户金融目标须明确说明并取得相应授权 |

“数据卡住即停”适用于依赖该数据的实证执行，不是要求整个项目停工。第一轮 R2 未复核不自动阻断第二个无关接口的合成测试；旧 Stage4 归因失败也不自动否定现任 K1。当前基础设施任务本身不运行新训练、选容量或账户。

## 3. 方法选型前：一份简短研究说明足够

说明：金融需求、预测对象/期限、决策时可得信息、候选数学机制、为何能影响横截面差异、最简单基准、可证伪条件。提出新因子、算子容量、残差模型或条件交互时，都要能回答它改变了哪个可验证机制，而不是因工具新颖就采用。

经验比较在查看对应结果前记录主要评价量、支持集合、尝试预算与停止原则；探索性修改可以继续，但追加到同一实验记录，不能把试过的选择隐藏为首次验证。参数由问题和资源决定，不强制统一阈值、种子数、K1→K2→K3 顺序或残差模型类型。用户已明确授权且边界清楚时，不逐步重复请示。

普通文案、索引、反例和接口维护用 Git 提交及针对性测试即可；不需要每次重新冻结全仓、不要求五份新报告齐全才提交。预测对象、数据口径、模型或正式结果发生变化时才更新相应合同/实验身份，并同步真正受影响的文档与测试。

## 4. 数据过大：把执行放在数据所在位置

允许三种证据层次，但不可混为一谈：完整数据在云端则可独立复验；原环境本地执行后返回小回执，则标明外部执行及云端验证范围；有界切片/反例则只能支持所覆盖的断言。摘要和日志不能单独证明全部 PIT，抽样通过不能宣称全量通过。

一个有用的小回执应包含：运行代码提交、输入路径与摘要规则、命令和实际退出码、运行环境、覆盖日期/股票/时钟、检查项与失败明细、输出摘要、未检查事项。包含必要的小型合同、schema 和来源定位即可；不要默认上传整个 DataHub、重复 isolated 树、所有原张量或全部历史结果。

先做最小来源索引和决定性反例；发现确需某项原始数据时，解释它会改变哪个判断，再取其最小有界依赖。已经验收且身份未变的 R1 输入不重复上传。原文件找不到时保留不可复现标记，可以提出独立后继实现，但不称为找回了原过程。

### 可执行的本地元数据盘点

在拥有原文件的机器，从本仓库根目录运行 [只读盘点器](../../scripts/reaka_local_source_receipt.py)：

```bash
python scripts/reaka_local_source_receipt.py \
  --request cloud_results/first_round_rework_20260906/recovery_request.json \
  --input-root /path/to/FactorLab > local-source-receipt.json
```

把输入根目录换成真实路径，输出选一个新的非历史文件。程序只读取恢复清单中的有界路径，不递归追整湖，不调用旧训练/账户脚本，不将行情数组或源码正文写入回执。输出含相对路径、大小、实际 SHA-256、原预期及摘要口径、缺件/不符/未绑定项、采集器和清单摘要。大文件采用分块哈希，数据本身无需上传；这里只盘点，不取代后续断言所需的本地计算。

退出码 **0** 仅表示盘点项没有缺失/未绑定；**1** 是无效请求、读取错误、读取期间文件变化或明确字节不符；**2** 是缺失/未绑定，JSON 仍可用于定位。三者都不表示 PIT、历史复现或经济验收。P6.2 原摘要规则尚未恢复时，raw 与 canonical 仅作为候选记录，即使其中一个匹配也不自动放行。两份旧账户来源缺口仅保留，不伪造修复。

**本轮工具是来源元数据盘点器，不是完整 R2 PIT 验收器。** 原环境后续验证需补充上述运行身份、时钟覆盖和断言结果；摘要和小回执不能单独解除 R2，也不能证明没有泄漏。本地机器不存在相应文件时，保留未知，不再把整湖上传当成所有其他任务的前置条件。

## 5. 验证命令及其含义

```bash
python scripts/validate_reaka_foundation.py
python scripts/validate_reaka_foundation.py --inventory
python scripts/run_infrastructure_tests.py --output foundation-validation
```

第一个命令检查现行路由、稳定语义、任务状态结构和现行链接；第二个同时列出全仓 Markdown 导航情况，历史断链是报告项；第三个运行当前可执行的全部单元测试，明确列出已知缺依赖历史模块。新增测试默认纳入，已纳入的测试发生收集错误、失败或跳过均不能报通过。报告保存精确命令、JUnit、版本和实际提交。

浅克隆运行历史合同反例前：

```bash
git fetch --no-tags --depth=1 --filter=blob:none origin 3a75376e1f7f871bb72e48f886c275919b3c9671
```

V1.3 测试读取该固定修订的旧字节，而不是要求当前 README、工作流和源码永久等于旧摘要。日常文档不再承担实验产物的字节冻结职责。原合同与原摘要本身不改写。

严格全量检查保留：

```bash
pytest -q tests/unit
python scripts/validate_theme_package.py
python scripts/audit_reaka_foundation.py
```

它们分别检验所有单元模块、登记数据、旧 current@1.2 证据。缺模块或旧证据失败必须报告，不能跳过后说全仓通过。默认 CI 只运行当前基础设施；手动选择 `dataset` 或 `full-unit` 才执行对应大范围任务。旧证据报告也改为手动，避免每次改文案重复下载行情和复述已知失败。

`python scripts/validate_reaka_foundation.py --historical-v1-3 --root PATH` 只验证一个正确还原的 V1.3 目录。对演进后的工作树运行旧字节合同出现漂移是预期区别，不是修复旧摘要的理由。

## 6. 哪些约束不应增加

不要求市场/行业中性，不要求残差非零或必有盈利，不要求必须 DDPM，不把原始矩阵距离当金融识别，不把 Stage3 描述性统计当容量选择证据。没有“所有旧缺口清零才准做下一件事”的总门，也不要求所有文档都进入一个全仓白名单才可编辑。

硬约束来自正确性：可得时间、标签成熟、相同收益与复权口径、无未来泄漏、同支持比较、真实证据身份和诚实报告。生产和用户本地指针始终不由仓库检查器授予。既定数据边界按原用途声明执行；扩展未授权数据范围不属于普通修订。

历史写入型 launcher 仍是退役入口，不能为绕过限制而启用它覆盖旧结果。需要新研究时编写或适配隔离的后继入口，只复用可安全独立调用的数值组件；不要把旧写入守卫当成全项目禁止研究的理由。

## 7. 交接完成标准

说明本次改动和对应理由，提供可定位的提交、实际测试/检查及其范围，列出仍未验证的结论，并给出一个下一动作。状态只更新状态文件；不把数值结果复制到所有入口。基础设施、文件完整性、历史复现、预测效力和经济结果分开写。

有阻断时交付已经完成的独立工作和最小恢复条件，不反复要同一批大文件，不等待无关门变绿，也不承诺离线继续运行。
