# 云端数据访问与计算前质量检查

2026-09-13。面向Chat和获授权本地控制器的操作备忘，不是扩大工具权限或解除平台安全检查的规则。公库只保存通用执行器与非敏感说明；数据、论文、策略源码、详细质量报告、股票剔除清单和结果均保留私库。现有冻结profile不由本文自动改动。

## 1. 先固定身份与来源

先读取本分支AGENTS.md和docs/public_execution.md。核对实际仓库、分支/提交、路径、文件类型和大小，再按当前工具schema选接口。Chat连接身份、公库job的GITHUB_TOKEN、环境中的私库令牌是三个身份；不要因一次失败扩大授权或重复配置。已核验配置无变化时不重复接入小样。

## 2. 小文本、较大文件、二进制和大数据包

| 对象 | Chat优先方式 | 有原始字节能力的已授权控制器/执行器 |
|---|---|---|
| 小型UTF-8文档、JSON、源码 | fetch_file固定ref并按行读取；先清单后正文 | Contents接口；记录完整文件摘要，局部读取不是完整验签 |
| 超过1MB且不超过100MB的仓库文件 | 不假定当前包装工具支持大文件或二进制；若只供阅读，用私库明确标注且绑定原件SHA256的文本副本 | Contents GET配Accept: application/vnd.github.raw+json获取原字节；object媒体类型可能只返回空content及encoding=none。也可用合规Git或Git Blobs API，确认实际收到非空正文 |
| PDF、Parquet、NPY、压缩包 | 不用UTF-8 fetch硬读，不把base64字符串交给文本create_file后冒充原文件 | 使用明确支持二进制的客户端，流式落盘并验长度/SHA256；Git blob编号不是跨仓库自动存在的对象 |
| 超过100MB或多分片研究包 | 只读目录、manifest、契约和私库结果摘要；不把全包送进对话 | 从既定私有Release按资产ID下载，Accept: application/octet-stream；核对200/302、可信重定向、每片顺序/大小/摘要及包内清单，按冻结manifest限定解包与消费范围 |

这些1MB/100MB边界来自GitHub Contents API，并非所有Chat工具的容量承诺；工具可以有更窄限制。raw是HTTP媒体类型，不是给UTF-8专用工具换一个URL就能取得二进制。下载URL可能过期，不长期保存带授权参数的链接；跨主机重定向不转发Authorization，使用现有broker的目的地主机白名单。

原字节跨库迁移必须先取得源字节，在目标创建对象并提交，再从目标提交回读校验。只记录路径、源SHA、下载地址或创建悬空blob都不算迁移完成。论文原件留私库，阅读副本说明页码/提取方式；图表和公式仍以原件为准。

## 3. 写入、错误与合规边界

新文件用create_file；改现有文本先fetch_file取得当前blob SHA，再update_file提交完整UTF-8内容；同路径串行操作，发生并发冲突先复读检查，不能强推覆盖。只作任务必要的有界改动，不批量覆盖基线、不夹带秘密。正常接口分工与减少不必要数据属于请求正确性，不承诺降低未知安全规则的拒绝率。

UnicodeDecodeError、非UTF-8拒绝、空正文先查文件类型和接口；422看具体校验原因；401/403/404区分调用身份、路径、权限、套餐端点和令牌状态；限流依Retry-After或速率重置时间有限重试。不要用重跑旧job替代workflow_dispatch，也不要把API有接口当成当前Chat已暴露该动作。

真正的OpenAI安全拒绝只记录脱敏动作、目的、路径、时间与原话；未知原因由用户负责研究。本项目不做试探性拒绝实验、不为消除拒绝关闭安全设置、不通过换端点、编码、拆分或工作流隐蔽重试。独立且获授权的其他工作可以继续。

## 4. 新研究profile的数据质量前置门

固定流程：取包与验签 -> 隔离容器内模式/单位/时钟/预期股票日期轴检查 -> 决策时可用性与关键因子覆盖检查 -> 冻结研究支持/隔离名单 -> 成熟标签支持诊断 -> 获准的归因/训练 -> 独立验收 -> 私库回存。

运输成功不等于研究数据合格。必要输入或必需指数缺失时，受影响的行、证券或模型不能静默通过。长期停用证券/指数必须有当时可知的来源证据和预先登记政策；不能按未来收益或未来覆盖率倒推删除整个历史标的。停牌、上市前、非交易日、结构性零、真实缺失及无效/迟到数据分别标记。对已有持仓，数据不可用不等于可以按零价格清仓或凭空移除。

质量结果至少区分PASS、QUARANTINE_ENTITY、HOLD_MODEL、FAIL_INPUT、INCONCLUSIVE_LABEL_SUPPORT；详细阈值、白皮书、manifest与例外处理由私库冻结。必需指数缺失应停止依赖它的模型/时点，不把全市场股票一律判坏。未知/不完整检查结果不得默认PASS。

诊断任务可为定位缺失读取获授权、已成熟的标签，标记diagnostic_only；其输出不能反写决策时股票池，也不授策略执行或因子晋级。没有合格数据时可以完成诊断，但不能宣称金融验证通过。

现有baseline和既有研究profile按原固定身份保存。新profile须实际接入质量检查、固定源码与输入摘要、独立验证和资源预算；未实现/未注册时只报告文档或代码准备，不称门禁已经在云端生效。公库日志仅显示固定非敏感状态码，缺失分布与具体股票/指数只回私库。
