# 策略自然年研究会话—整案重建白皮书

## 1. 方法论地位

这不是某一个策略的调参技巧，而是 FactorLab 的项目级策略开发方法。V5 证明分段反例能改善整案；V6 又证明切得更密并不自动更科学：若把相关症状逐条升级为硬否决，观测分辨率越高，越容易把候选空间压回基准。

核心是“共同起点、并行隔离、逐年盲测、开放归因、每年整案重建、逐年封账”。

## 2. 为什么长区间会制造假优秀

长区间目标函数是加权平均。一个时期的大利润可以遮住另一个时期的结构性失职；一个优先桶的收益可以遮住其他责任桶的误认领。因此“2009—2017 很好”不能证明机制普遍，只能证明该期间总和为正。

切片之后，目标不是让每片都产生高收益，而是迫使研究者回答：

- 当时是否有相应机会；
- 完整策略为什么没有拿到或为什么误认领；
- 责任属于哪个机制；
- 是否存在一个非日历、可实时观测的共同根因。

## 3. 为什么并行版本不能相互参考

版本号容易制造继承错觉。若 V5、V6 和新实验事实上都从 V4 分叉，那么把 V5 的优胜桶、V6 的失败条件或旧 V7 的候选空间交给新实验，就等于提前泄露答案。年度会话再细，也只是在既定答案附近重复测量。

因此隔离不是“尽量少参考”，而是源级硬边界：并行实验只共享共同根公式、原始行情载体和通用评价工具；策略公式、参数、问题台账、候选族、选模结果、黑箱结果和研究结论均不得跨支线流动。污染发生后不能靠删一列补救，必须从共同起点重启。

## 4. 为什么取消半年错位滚动

V6 的半年错位窗在统计上只是边界视图，却在硬门中仍然拥有逐条否决权。23 个窗口最终形成 138 条记录、70 条硬材料，而可归并的根因类别只有 6 个。错位窗提高了记录数量，没有提高根因认知。

更现实的问题是研究执行质量。二十多次窗口若被一次脚本批量处理，AI 很容易把“完成表格”误当成“完成研究”。因此当前合同只允许十二个自然年：

- 每年是一场完整研究会话；
- 自动化只负责准备同口径证据；
- 人工/主代理负责解释、归因、约束审查和台账；
- 不允许用 shell 循环或批量驱动器把十二次会话压缩成一次运行；
- 上一年没有封口回执，下一年不能开始；
- 每年开放归因并预登记后，允许执行当年的有界整案重建；十二年完成前，不允许把任何年度快照冒充最终验证版本，也不允许一次性批量生成十二年的最终排名。

## 5. 观测、根因与硬义务是三种东西

年度负收益只是观测；解释这种负收益的共同机制才是根因；只有被独立年份重复支持或被冻结因果挑战支持、且有经济意义的已解决根因，才可以晋级为硬义务。

基础设施强制：

- 原始观测和未解决根因不能成为硬门；
- 同理，事件覆盖率、错向占比等诊断量在根因晋级前只能参与排序和解释；即使差异很小，也不能以零容忍门否决完整账户的全面改善；
- 同一根因最多产生一条硬义务；
- 硬义务数不得超过候选族有效自由度；
- 若当前候选族不能解释根因，应报告候选族不足，而不是继续增加否决项；
- 基准是比较器，不是新版本候选；账户路径等价基准也不构成后继。

## 6. 为什么必须每年“整案推倒”

增量补丁会让新块同时成为问题来源、规则训练集和过门考卷。即使每次只增加一条小规则，长期容量仍会无上限。

每个年份承担两个严格分离的角色：先作为上一快照的盲测年，随后在盲测结束后转成当前支线的新开发材料。看完问题后必须先预登记本轮有界候选族，再从共同起点重建完整策略；上一快照不能作为代码父类，也不能通过增加局部规则存活。

这里反对的是“失败一年就补一条日历规则”，不是反对一切新增层。若一个新增项是低自由度、入场时可因果观测、生命周期内冻结的否决门或二选一路由，它可以被定义为一套完整候选。对于已经消费的历史，不能只报 pooled 改善；必须看它实际改变了哪些年份、其中多少年份改善、有效年份中位数和贡献集中度。当前项目默认用“至少 3 个有效年份、至少 60% 为正、中位增量非负、总增量为正”作为回溯研究冻结门。该门解决的是稳定性筛查，不把回溯结果变成新鲜样本外证据。

这不意味着每年都必须获得行为不同的公式。证据可能支持账户等价结果，但回执必须证明它来自一次完整重建决策，而非默认继承。下一年只检验上一年封存的快照。2020 年重建出的最终快照没有后续新年份，因此不能声称已验证。

## 7. 什么才算验证

滚动切片的全历史重建只是 retrospective stress research。它能证明“当前有界族中哪个完整方案最能经受已知反例”，不能证明未来。

真正的挑战必须：

1. 在打开新期间前冻结唯一公式和经济底线；
2. 不排名其他候选，不调参，不修正公式；
3. 无机会只能不确定，有机会且跌破冻结底线才是失败；
4. 失败期间转入开发材料后，不得再验证由它参与重建的新策略。

## 8. V5、V6与旧V7的证据边界

V5 已经在 2021—2026 执行过一次整段聚合黑箱。这段证据对 V5 有效，但一旦结果被人类和研究流程看到，它就不再是 V6 的新鲜数据。即使不打开年份细节，聚合结果也不能反向参与 V6 排名。

V6 使用 2009—2020 建立年度/半年错位材料图谱，但其逐窗零容忍硬门把 `paper_up` 的条件性冲突处理成了整项删除。重复聚合复核显示 V6 与 V2 账户完全相同并落后 V5，证明这是稳定但无增量的欠拟合解。

V5、V6、旧 V7 不能形成继承链；它们是共享 V4 共同起点的并行实验。旧 V7 因直接重选 V5 行为而不满足隔离条件，保留为负面方法证据，不得成为新支线设计素材。新支线仍只允许使用 2009—2020，2021—2026 的任何已知细节或聚合结果都不得参与选模；完成后只能等待真正新的未来时段。

## 9. 权限

本方法授予研究和审计权，不自动授予参数权、路由权、架构锁定权或生产权。任何历史内重建胜者都必须带有 `fresh_oos=false` 和 `production_authority=false`，直到真正新数据完成因果挑战。

封存包的源码摘要描述的是“当时到底用了哪些字节”，不是要求现行
Skill、工作流和验证器永远不再演进。正确的长期校验应先比当前文件；
若当前文件已升级，再到 Git 历史中寻找摘要完全一致的旧 blob。找不到
精确字节时必须失败；为了让旧测试变绿而把封存摘要改成当前摘要，同样
属于篡改证据。

## 10. 渐进材料与候选晋升分层

`strategy_annual_session_rebuild@4.0` 保持历史语义。当前 successor 是
`strategy_progressive_development@1.0`：硬原理失败仍是零妥协；通过硬门后，
同口径主目标改善只需超过确定性重放容差即可保留，不设置最低经济强度。年度、季度、
成本、风险和跨 variant 稳定性仍可阻止候选晋升，但不得删除该 progression material。

收益、回撤、容量或时钟存在未预先解决的金融权衡时，状态是
`progress_tradeoff_waiting_financial_owner`。AI 不得结果后发明效用权重。

## 11. 训练后账户审计成为标准阶段

每轮模型、因子分数或策略分数冻结后，必须在 closeout 前执行
`post_training_account_audit@1.0` 的 A0—A7。该阶段冻结并测试 TopN、权重、买入受阻、
集中度、成本压力、时钟/variant 和完整账户；formal/isolated 必须一致。旧政策盲测只
允许一个 policy id，主控审阅后才可用第二个命令打开完整候选族。最终 validator 必须
同时接受“有合法赢家”和“诚实无赢家”，不得把某次 REAKA 结果写死为通用预期。
