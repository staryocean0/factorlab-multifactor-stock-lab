# R3 后继评价设计：前缀选型隔离、同环境 F/H 与可重载产物

日期：2026-09-06。设计编号：`R3-TIME-ISOLATED-DESIGN-20260906-01`。
依据提交：`1b3bd7ac41a95343134b2f32bb57d9e496b2a0bf`；开发分支 `codex/reaka-foundation-audit-20260905`。
**这是云端与本地协作中的云端设计工作。当前没有派发本地任务，没有训练或打开新的评价标签。**

## 1. 结论：需要的是新评价对象，不是给旧结果补签

旧 R2、NOFIT 和 F/H 任务均已按原范围收口。已消费2017上的 F−H 线索保留；CPU/CUDA混用、历史数值身份未完整绑定、H没有保存权重等事实不改写。见[上次验收](../../cloud_results/local_handoff_R3_condition_20260906/cloud_delta_acceptance/cloud_review.md)。

本次设计选择一个最小、可实施的后继：**2016年底统一冻结选型与模型；在2018—2020既有材料上做固定原点、同环境、成对新建的 F/H 比较。**不增加 E、K、残差网络或超参数搜索，不继续使用2017挑选配方。

它提高的是两种证据强度：第一，选型决策不再读取评价期结果；第二，F/H数值实现、数据支持及运行环境有直接可核的配对身份。它**不能**将已消费资料变成fresh OOS，不能证明未审计的外部PIT或成交性，也不证明经济因果、Koopman独占贡献或真实账户alpha。

本方案是这一实验的冻结选择，不是给全项目添加永久阶段顺序。新结果为零、负、混合或未决均可接受为研究结果；不允许为了正数换年份、阈值、种子或模型。

## 2. 为什么选择这些时段

仓库[数据用途声明](../governance/data_usage_declaration.json)将2007—2008列为预热、2009—2016列为开发、2017列为内部review、2018—2025列为已消费重复比较且不回调；2026明确隔离。原K1输入manifest的实际日历止于2020-12-31，inference从2011开始。[S1][S2]

因此本次不将2021—2025日线“已有”误解为盘中K1输入、因子状态和H20标签已经齐备，也不为扩大年数新造DataHub任务。

| 区间／时点 | 本实验用途 | 不允许的用途 |
|---|---|---|
| 2007—2008 | 原始历史和滤波预热，不纳入选型/训练成绩 | 不扩大训练年数来满足阈值 |
| 2009—2016 | OT工具选择；仅使用冻结点前已成熟的收益结果 | 不读取2017—2020 future来选工具 |
| 2011—2016 | K1历史epsilon表示训练、DMD、normalizer及选cycle | 不用future epsilon筛训练行或选cycle |
| `2016-12-31T23:59:59+08:00` | 研究中的拟定冻结点；实际cutoff取原交易日历中此前最后可用观察 | 不伪称2026才写下的方案在2016已被研究者预先登记 |
| 2017 | 已用于设计的review，不计本次主结果；可提供2018预测需要的历史窗口/滤波连续状态 | 不再调参、选工具、更新模型或选checkpoint |
| 2018—2020 | 规则和模型不变的重复比较；两时钟、各seed、所有年份完整报告 | 不回流到选型、训练、normalizer或周期选择 |
| 2021—2025／2026 | 本方案不读取；前者不是因为“未消费”，后者继续隔离 | 不自动扩大数据范围，不宣称它们可用作fresh holdout |

**年末标签尾部**：按原真实交易日历的H20标签成熟点裁定，不按“日期加20天”。2020年末仍输出预定行的预测，但目标尚未在现有日历内成熟的行不能评分；先记录这种目标可评价性，再对所有臂采用同一掩码。不为尾部标签额外拉2021数据，不把无标签行从预测样本中先行删除。精确行数和最后可评分决策日留待实际日历计算，本设计没有编造它们。

选择单一冻结点而非逐年重训，是为了只改变必要环节并限制成本。其结果描述“一套冻结到2016的模型随后三年的表现”，不描述滚动更新策略。模型陈旧导致负结果是该估计对象的一部分，不据此事后加滚动训练。其他任务可以另选滚动方案，不把这一选择普遍化。

## 3. 先解决选型时钟，再生成共同输入

### 3.1 必须在聚合前隔离成熟结果

原 `evaluate_annual_tools` 先将state与`future_basis`拼接，再按`aligned.index.year == year`过滤；这只约束决策年，没有检查收益标签实际成熟时间。[S3] 例如12月的H20收益可能在次年成熟，不能因为其决策日在2016，就允许2016冻结时使用。

对候选行q，至少记录：决策时点d(q)、候选信号原始依赖的最晚时点x(q)、目标及其所有计算依赖的最晚成熟时点m(q)。选型可用集合为：

`2009开始 <= d(q) <= 冻结点`，`x(q) <= d(q)`，且 `d(q) <= m(q) <= 冻结点`。

未知成熟时间不能按决策日期替代；入库`available_at≈2026`不自动等于历史可得时间；带Z的字段不能不经规范就改成上海墙钟。这里是对已声明观察时钟的隔离，外部可得性没有证据时仍须明确条件。

**执行顺序**：先由来源坐标计算成熟掩码，物理限制传给选型器的future行，再做年度汇总。不能先用完整2009—2020汇总选好工具，再在报告中把年份裁短。候选状态允许从更早预热历史因果生成；换手率的上一状态依赖也必须来自已知历史，不能以删除未成熟目标后的跨缺口差分冒充原相邻换手。

### 3.2 固定候选集、评分规则与退化选项

使用原OT2七个eligible代表：laplace IIR混合带通、IIR低通、Butterworth清洁带通、因果Haar带通、布林通道、因果趋势线、均线趋势。其精确ID、参数、预热规则和过滤代码随运行快照保存；不得凭本次结果新增代表、翻转方向或修改阈值。[S4]

按原经济family（market/size/industry）独立选择，原门槛保持：每工具至少6个supported年，正增量年比例至少0.60，中位增量非负、总增量和candidate net为正，正增量集中度不超过0.60；年度至少20个决策日。按中位增量、总增量降序，tool ID升序处理并列。无合格工具则保留原 `naked_residual_level_follow_control_v1`，**不降低门槛以保证有新工具**。7bps是原选型代理统计的成本口径，不是本实验真实账户费用。[S3][S4]

候选与naked必须在相同factor×date标签支持上比较后再聚合family；原实现先聚合再按family/date匹配的支持限制应单独报告，不让工具因为省略困难行业获得虚假增量。该修正属于后继选型定义，不回写旧selection或旧年度指标。

选型仍可使用full_reference的训练前缀；之后将这一冻结family工具应用于**5个实际消费cross-fit分支×14个因子×2时钟**。这只提供截面排除结构，不把cross-fit当作时间隔离的替代。每个序列用冻结工具生成到当前决策为止的历史，覆盖真实使用的全部分支，不只检验variant0。

### 3.3 可以复用什么，必须重建什么

P6.1价格/收益、OT1 history/future因子基底和epsilon、历史暴露的原已审计算术可作为有身份的共同原料；使用前只检查本实验直接依赖，不重开R0/R1/R2大盘点。外部成员表时点、修订价源等未证限制继续约束结果。

旧2009—2020全区间selected工具、`selected_factor_states`、P6.3状态值及其可用性掩码**不能默认复用为新前缀选型产物**。必须生成独立后继selection和状态，装配新共同输入；若实际选择碰巧相同，也须由前缀流程产出的身份与数组证明，而不是改旧文件标签。

推断行按历史epsilon/可得性规则生成，不按未来标签或F/H预测好坏选样；X不可用由原71通道掩码表达，不因H不需要X而给H单独更多股票。保持股票轴、因子轴、变体映射、D5/四相位、十个间隔20交易日历史端点和稳定tie-break一致。第70通道仍是原零占位。

## 4. 新建可比 F/H，而不是沿用旧 CUDA F 和丢失权重的 H

本次未来主比较记作 `F_new` / `H_new`：F保留新前缀选型生成的直接X，H在normalization之后将全部71个直接X通道置零。H保留原网络拓扑、feature encoder和gate，保留相同金融epsilon历史。**它不是“完全没有因子信息”，因为epsilon已做上游残差化。**

固定配方沿上轮选择：latent=8、hidden=8、K=1、r0、Adam LR=0.03、weight_decay=0、batch=4096、三cycle、seed11/29/47、14:30/14:45。不是论文唯一正确参数，也不是本次重新优化所得。[S5]

一次实验使用同一封存代码包、同一Python/torch/numpy/scipy/BLAS版本、同一backend/device及确定性设置，优先同一CPU环境；不得F用历史CUDA、H用新CPU。记录dtype、线程、torch deterministic开关、CUDA/cuDNN（不用也记录无）、TF32/AMP状态和实际导入模块路径。PyTorch官方明确同seed不保证跨CPU/GPU或跨版本重现，因此不能用seed相同替代环境一致。[S6]

每个clock/seed先建立并保存**同一预DMD初始state**，独立克隆到F/H，再分别按其特征视图估计DMD，各自新建optimizer；禁止F训练后或F-DMD状态warm start H。相同seed/cycle的样本遍历完全一致，初始state和遍历摘要相同；训练后的参数、DMD和loss不要求相同。

一个共同normalizer只从新共同训练前缀计算一次，保存完整数值正文供两臂使用。禁止从评价期估尺度，也不把旧formal中不存在的normalizer摘要推断为新记录。模型继续学习历史窗口的重建与潜转移，不改为监督拟合future epsilon；future不能进入DMD、fit eligibility、训练batch或选cycle。

周期选择保留原canonical loss：固定训练索引前一个batch，最小者入选、平局取最早；不拿跨臂潜loss大小作金融优劣。每臂独立选cycle，不按2017或2018—2020成绩选择。DMD、训练、canonical loss及forecast四处都走同臂输入视图。

**评价标签隔离接口**：训练/预测输入视图不暴露`epsilon_future`；工具选择器只收到允许成熟前缀的因子目标。保存全部选中模型与预测分数后，评分端才载入评价标签。原`score_rows`若同时取出target，后继必须提供prediction-only分支，不能只把返回值命名`_targets`就称未读取。

## 5. 运行时保存，而不是事后补写持久化声明

一份实验run目录即可，不新增多重审批或五套重复报告。必须在删除内存模型前完成以下保存并记录真实文件身份：

| 产物 | 最少内容 |
|---|---|
| 运行身份 | 设计/配置、实际源码快照或patch、直接数值模块与filter依赖摘要、环境、输入身份、所有失败尝试 |
| 选型与normalizer | 成熟前缀坐标、工具/参数/支持摘要、完整normalizer正文及其raw/canonical明确口径 |
| 每clock/seed | 共享预DMD状态、遍历身份、F/H各自DMD/训练损失/所选周期 |
| 每臂选中checkpoint | 所有state_dict张量、名字/shape/dtype/摘要、模型配置、输入view、normalizer与source/env绑定；需要续跑才另存optimizer/RNG进度 |
| 预测与坐标 | 分数数组、原始坐标顺序、股票/日期映射、可预测行与成熟标签掩码、每seed和集成结果 |
| 重新载入检查 | fresh模型对象加载已保存权重与normalizer，实际预测并和首次输出比较；不能只检验文件存在 |

可复用原 `save_state_tree/load_state_tree` 的张量存盘思想，但必须绑定本次config/arm/normalizer并在**第一次**运行保存。`artifact_inventory`会逐一重算checkpoint目录下所有文件的raw SHA-256，不信任JSON自带的旧摘要，不把只有scores当成有checkpoint。

重新载入：张量和坐标身份精确一致；完整有界评价分数按预定atol=1e-6、rtol=1e-5比较，并单列rank变化、ties和指标变化。数值近似但名次不同不能签“排名完全重现”；保留差异，不事后放宽容差或以重训掩盖。评分以绑定的保存分数为准。重载与二次预测属于未来运行的验收步骤，本次没有执行。

原H权重没保存的事实仍保留。未来新H拥有新的身份，不能冒充恢复旧H。新F也不是替换现任，而是同环境对照对象。

## 6. 配对评价与证据升级边界

每个决策日、每时钟，用相同股票/标签支持计算`RankIC(F_new)-RankIC(H_new)`。先保留每seed，主分析沿原逐日rank-z后等权种子集成；不挑最佳seed。四个无需拟合的历史规则完整报告，不事后只保留赢家。

预设一个总体主量：**每个共同预定D5日将两时钟差等权平均，再按日期等权平均**。两时钟各自的结果同时完整报告，不把它们算作两个独立实验。不静默取表现较好的时钟、日期或股票交集；若同支持无法建立或有非有限预测，先定位执行失败，附缺失表，不把困难样本删掉后宣称完成。

辅助项：配对中位数/胜负日、全部三个年份、四相位、H20残差十分位差、Top30相对同股票全集的均值。后两者仍不是股票总收益或扣费账户收益。年度差异作为稳定性/衰减描述，不变为下一轮年份筛选条件。

**依赖处理预案**：未来在完整预定D5时间格上，对F/H配对差做移动时间块重抽样；两时钟使用相同块索引。主块长8个D5间隔，敏感性4和12，5000次、固定seed61207、95%区间；这些是事前记录的有限敏感性设定，不是“4个间隔后一定独立”的定理。缺数据保留时间格与缺失mask，块内一起抽，不压缩掉日期缺口；任何方案不足3个块时不输出貌似可靠的区间。按年展示不跨模型原点的问题：此处只有一个固定模型原点，非滚动重训。[S7]

这一步的统计实现尚未接入真实数据，本轮不计算新p值。区间以相关序列的近似重抽样假设为条件；不能修复元研究反复消费、原始数据时点不明或选择过的配方。不同块长结果冲突要完整披露，不选显著的一个。

| 未来观察 | 允许的裁决 | 不允许的补救 |
|---|---|---|
| 主平均差≤0 | 不支持本固定后继中的正条件增量 | 加seed/调K/换年直到转正 |
| 差为正但区间/年份/seed混合 | 回顾性增量线索，强度未决 | 写成“稳定显著条件alpha” |
| 差为正且预定敏感性一致、接线/身份成立 | 在该已消费代理目标与冻结方案上，更可信的时间隔离算法对照证据 | 恢复fresh OOS、签外部PIT或净账户收益 |
| 来源/时间/重载检查失败 | 对应执行项或对应主张未获证实；保留已成立独立结果 | 把失败当策略负收益或重封旧摘要 |

即便后继成功，训练配方与候选集是在看过旧结果后定的，经济因子/成员池也可能有历史设计信息；因此不是从未接触样本的独立确认。真正前瞻证据需要另行定义此前未消费的资料和可用时钟，不能擅自启用2026。

## 7. 成本、复用和实现顺序

若将来进入执行，最小主预算是 **2臂×2时钟×3seed=12次新拟合，最多36cycle**；一对成对运行即可，不必先完成整个F后再做H。各臂各自DMD和normalizer前缀计算、存盘重载以及评分单独记账，不计作额外模型搜索。与上轮6次H不同，本次不能默认复用旧F/H：选型/共同输入改变、后端和运行身份必须配对，且旧H不可加载。

这只是未来实验预算，**本轮新拟合=0、新推理=0、本地派发=0**。断点续跑允许保持同一预声明配置并记录实际额外耗用，不能把新增随机重启隐藏成原12次。无需额外人工逐年签字；停止条件只针对真实数据/数值问题与资源上限，不针对是否盈利。

未来实现先后次序（不是本地当前待办）：

1. 在同一只读小预检里确认直接数据路径、交易日历、目标成熟坐标、候选filter及同环境可运行性；不重复整湖盘点。
2. 接入物理前缀选型，生成共同后继状态和训练/预测输入；验证未来目标扰动不能改变selection、normalizer或预测，检验实际五变体状态前缀。
3. 将原纯数值训练方法接入新的隔离runner，F/H共享运行身份、独立DMD、四入口view一致；完成实际模型小batch接线及保存—载入测试。
4. 只有这一实施任务确已授权且上述直接依赖可用，才运行冻结的12次拟合与有界评价。缺数据步骤按AGENTS写沟通文档由用户转交，不把任务声明成本地已自动执行。

目前没有完整的后继选择/训练runner，也没有“可直接一键训练”的命令。现有主runner针对旧2017材料，不要直接重跑它来实现这个方案。

## 8. 本轮实际交付和验证
