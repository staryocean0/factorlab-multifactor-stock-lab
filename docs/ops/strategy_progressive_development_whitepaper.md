# 策略渐进开发与训练后账户审计白皮书

## 1. 这次修正什么

历史 `strategy_annual_session_rebuild@4.0` 正确解决了时序、分支污染、整案重建和假 OOS，但它把“进步材料是否保留”与“当前轮是否晋升新策略”混在一起。稳定性门失败时，合法、可复现、同口径的弱改善容易被简化为 `no_increment`。

新治理不降低金融或数学标准，只把不同权限拆开。

## 2. 横在所有收益之前的硬门

以下任一失败，收益不能补偿：

- 金融语义或经济符号错误；
- 数学恒等式、单位、会计守恒或梯度语义错误；
- 未来读取、非 PIT 输入、错误成交时钟或锁定箱复用；
- 不完整账户、成本缺失、不可交易性伪造或公司行为记账错误；
- formal/isolated 不一致、source closure 不可恢复、尝试次数未入分母；
- 未经授权的参数、路由、指针或生产升级。

硬门失败只保留 incident 和反例，不保留经济结论。

## 3. 进步保留不设经济强度门

候选通过全部硬门后，若它在结果前冻结的主目标上、与同一比较器使用同一账户和成本口径，改善超过确定性重放数值容差，该改善必须保留。

保留不等于立即替换现任。年度/季度分布、回撤权衡、成本压力、多时钟一致性和多重尝试可以阻止“晋升”，但不得删除已证明的弱进步。每条保留材料必须同时记录伤害向量、贡献集中度、尝试编号和未通过的晋升门。

## 4. 四层权限

1. **Progression retention**：真实弱进步进入下一轮材料，不获得运行规则权。
2. **Candidate promotion**：通过预登记稳定性和经济责任门后，冻结为回溯研究候选；仍为 `fresh_oos=false`。
3. **Fresh validation**：唯一冻结候选在真正未见共同时间区间做一次性挑战，不得排名、调参或改式。
4. **Production**：另行通过容量、数据健康、运行监控、kill switch、回滚和用户金融授权。

## 5. 训练后账户审计 A0—A7

每轮模型或因子分数冻结后，必须在策略 closeout 前执行：

- A0 冻结模型、checkpoint、score 定义与数据角色；
- A1 在结果前冻结 TopN、权重、买入受阻、集中度、成本和时钟完整族；
- A2 使用策略适配器物化因果 score/market/group 输入；
- A3 验证 source closure、formal/isolated、数值等价和精确 workload 性能；
- A4 只盲测上一份冻结账户政策；
- A5 主控人工审阅后，才对完整候选族重价；
- A6 封存当年 blind receipt、analysis ledger、重建 receipt 和链式 session receipt；
- A7 用结果中性 validator 验证有胜者、无胜者、无机会和基础设施缺口等所有合法终态。

blind 阶段与 family 阶段不得共用一个命令。账户结果不得续训或联合微调已冻结模型。

## 6. REAKA P7 迁移语义

P7 的“最终无挑战者晋升、无时钟提名、无生产权”结论保持不变。但它不再被解释为“没有可保留的进步”：2014 的 Top50 双时钟改善、2015 的收益/回撤权衡、2016—2019 的 14:30 单时钟改善以及 2020 的跨时钟冲突，应进入下一轮 progression material ledger。

该迁移只索引已封存证据，不重跑 2009—2020，不改写旧 receipt，不产生新胜者。

## 7. 权限

本轮只升级研发基础设施。它不授予新因子、参数、路由、账户、指针或生产权限。
