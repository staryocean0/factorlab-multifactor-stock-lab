## 2. 关键结果的独立聚合

每时钟82,321个日期×股票坐标、49个D5决策日，2017-01-06至2017-12-29。比较对象始终是 **H20未来金融epsilon**，不是股票总收益或账户扣费收益。

| 指标 | 14:30 | 14:45 |
|---|---:|---:|
| F平均RankIC | 0.15992587044817144 | 0.16152574720082447 |
| H平均RankIC | 0.14405336863472630 | 0.14052618619419457 |
| F−H平均RankIC | **0.015872501813445145** | **0.020999561006629863** |

| Top30相对全支持均值的平均增量 | +0.4298973426个百分点 | +0.3832445343个百分点 |
| Top30指标F胜出日 | 25/49 | 27/49 |

以上均值与本地比较报告的对应字段一致。Top30并没有呈现几乎每天占优；例如14:30在一个相位上的平均Top30差为负。不能用正的平均RankIC直接推导集中持仓稳定盈利，更不能将重叠H20的这些差值直接年化。

### 必须纠正的归因文字

本地报告称“历史epsilon的表示学习解释了现任相对固定规则的大部分优势”。这一表述不被当前证据支持。

相对本次四规则中均值最强的 `negative_mean10_epsilon`：H−B约为 **0.0108325454 / 0.0061330873**，而F−H为 **0.0158725018 / 0.0209995610**。即便仅作标量差的算术分段，前者也小于后者。更重要的是，RankIC的比例或差值不是唯一的机制解释份额；不能进一步把F−H全部叫作某一因子的因果贡献。

准确表述应为：**在现有已消费样本中，H也高于这四个固定规则，F进一步高于H；不同信息输入、学习过程和训练环境的作用尚不能被表述为百分比归因。** H保留的是金融残差历史，本身仍包含上游残差化的信息，不是完全不含因子信息。

### 极小的基准精度差，不影响F/H主量

本轮14:30均值反转基准RankIC为0.1332208232482858，上轮为0.13322081415939867，差约9.09e-9。源码中原NOFIT先将历史转为float64再求均值，本次runner保留float32后求均值；2017-05-24出现相应并列秩差。云端用合成float32输入复现了“均值精度改变可以产生并列秩”。这不是重新核验该原始股票行，也不宣称只是凭汇总即可排除一切其他来源。

此微差不改变F/H结果或当前结论；不能写成所有B字节与指标逐位完全相同，也不值得为此重跑全部数组。后续沿原NOFIT精度统一即可，旧结果保持原位。

## 3. 干预与可比性复核

### 已经做到的部分

上传runner使用云端设计的 `condition_model_class(Stage6ReakaModel, "history_only")`；不是只在2017评价时置零。`_encode_and_gate` 是两个训练窗口和forecast共用路径，原DMD/canonical_loss调用同一模型的training_objective，故所读代码路径也应用了H视图。

H从独立随机初态出发，调用其自身的DMD估计；优化器独立；配置、样本排序公式及周期选择沿现任配方；未见用F已训练权重或F的DMD作为H起点。没有可选E、K/seed/LR搜索或根据新评价结果修改后续参数的分支。六份训练回执的最小canonical loss都与所选周期对应，数值有限并低于各自初始损失。

### 尚未由当前交付闭合的部分

**A. 核心数值依赖。** `verify_source_blobs`只绑定fit-prefix、training、preflight三个文件；构造模型时实际还导入本地 `reaka_paper_v1.py`、`reaka_stage6_daily_engine.py`、`reaka_stage6_parameter_calibration.py`。这些函数决定训练目标、编码/预测、初始化；它们不是无关全仓依赖。F-wrap与“当前本地base”的8行比较等价，不能单独证明这些当前依赖就是历史F使用的相同数值实现。

只需说明这些实际消费文件及关键函数的身份、与原F数值路径的关系；纯文档/守卫差异无需重训。当前快照hash本身不证明过去运行时字节，能由运行日志或保留快照支持则说明，不能支持就保留该限制。

**B. 标准化与坐标。** runner重新调用 `normalizer_from_store`，记录了摘要，但未在代码中比对原F的normalizer身份；input manifest相同也不是运行时所有数组重新验证的证明。优先链接已有且适用的R2/NOFIT身份检查，只补当前缺少的normalizer对应和review顺序摘要，不能把需求扩大成重扫整个因子湖。

**C. 后端差异。** identity_pre_result明确写了H在CPU训练、F复用cuda:0产物。它是已披露的执行选择，不是隐藏改参；但两臂并非所有执行条件完全相同。当前没有量化训练后端对F/H差值的影响，故不能无条件写成“唯一变化是X”。本轮不自动增加六次F训练去事后制造匹配；若未来必须回答严格后端一致的输入效应，再另立有必要的比较。原云端方案允许复用F但未充分落实后端等价，属于本次设计解释边界，不把它处理成本地必须无条件返工。

**D. 每seed预测结果。** six seed fit receipts记录的是loss、cycle及分数文件摘要，不是每seed的2017RankIC、组差与F/H配对。原任务第5节要求保留每seed和集成；当前只回传集成，不能据此断言每个seed均有相同方向的增量。六个现有H分数足以补出，无需训练或重推理。

**E. H权重。**本地反馈说模型权重留在本地，但上传runner只写H score.npy，随后删除model对象，没有调用 `save_state_tree`、`torch.save` 或其他权重落盘函数。无法从该源码证实checkpoint已经保留。若有脚本外另存，给路径、摘要及保存步骤；否则明确“该次H权重未留存”，保留分数的证据用途与不能重载模型的局限。**不要为填这个洞而重训后将新模型称作原模型。**

### 实际执行顺序的范围

原设计要求先冻结所有臂/seed再读新2017结果；runner实际上每完成一个H seed就生成该seed的review分数，且完成14:30后才训练14:45。但已读确定性代码没有利用这些分数选择后续种子、参数或周期的分支。本次如实记录顺序差异，不仅凭顺序就认定发生有利挑选，不据此重训。后继执行宜将评价整体后移。

### 局部判定漏洞，未推翻当前有限结果

## 5. 当前可以与不可以使用的结论

可以保留：在已经消费的2017标签、相同声明评价坐标上，复用的F集成平均RankIC高于新H集成；H高于四个固定历史规则。方向是值得继续研究的线索。

暂不能写成：仅直接条件特征引起了0.016/0.021增量、每个seed均有稳定增量、市场/行业/规模某一分项有因果贡献、第二轮新增月度条件有效、独立OOS、事件可得/可成交或扣费账户alpha。H仍使用金融epsilon；不能把H名称理解成上游没有任何因子信息。R2、旧Stage4及历史账户局限不重开也不取消。

描述性配对差可以接受；完整“同配方且仅X变化”的强主张不能仅凭集成均值和三个上层文件摘要签字。未知来源只限制该断言，不变成项目全局停工。
